## 1. 目标与范围

把现有五关横版动作游戏提升为视觉统一、动作清晰、武器构筑有明显差异、关卡机制值得掌握、可随时分段游玩的 IDE 游戏。

完成范围：一个主角、全部十类敌人、五个世界与五个 Boss、六把武器及进化、音画反馈、行为组合、环境交互、短任务、续玩、永久解锁、完整菜单和设置、插件稳定性与性能验收。第一段样板是验证方法，不能替代完整范围的交付。

工程默认：Java 17、Swing/Java2D、IntelliJ build 232 基线，沿用 Gradle 项目。使用精灵图片和分件/逐帧动画表现体积感；素材可来自离线 3D 预渲染，但实时 3D 不进入本轮。新增运行时能力优先使用 JDK，素材制作工具可以离线使用。

保留现有五关战役、二段跳、冲刺、近战、炸弹、连击、SUDO、升级、排行榜和 Lab 调试入口。联网、多人、云存档、赛季、商城与实时 3D 不在本轮范围内。

### M1.1 最小必要运行边界

- [ ] 将 `FixedStepAccumulator` 接入循环，以单调时钟推进真正的 60Hz 模拟，最多追赶五个 tick。暂停/恢复/隐藏后重置累计时间。
- [ ] 处理当前 16ms/tick（约 62.5Hz）到 60Hz 的迁移：按 M0 真实时间基线换算移动、重力、射击、冷却、预警和任务计时；有意调整单独列为数值变化。用注入时钟验证调度抖动、有限追赶和相同真实时间内的行为，不能隐式接受约 4% 的节奏变化。

### 素材完成清单

- 主角：1 套统一设计，至少覆盖 M2 中十种动作，并可显示六武器。
- 敌人：10 类全部覆盖必要的移动、攻击预警、攻击、受击和死亡状态；不同职责不强行使用同一套动作。
- Boss：5 个，三阶段均有可见状态变化、招式动作和死亡表现。
- 世界：5 套可辨识的远景、主体、地面、前景与至少一种机制交互素材。
- 武器：6 套基础与进化反馈，包括枪口、弹道/范围、命中和相关状态表现。
- 界面：武器、模块、资源、拾取物、状态与危险方向图标；正式交付不留临时占位。
- 音频：六武器、通用战斗/界面、五世界与 Boss/高潮状态；资源体积与混音上限在样板后固定。

## 12. 并行协作、风险与完成定义

接口先定后并行：运行负责人处理 `GamePanel/GameSession`，战斗负责人处理效果与成长，视觉负责人处理素材与 renderer，世界/体验负责人处理关卡和菜单。共享文件由一个负责人整合，其他工作通过接口和数据定义接入。

| 风险 | 处理方法 |
| --- | --- |
| 角色单帧漂亮但动画身份不一致 | 用统一源图/分件或离线模型，先通过 M2 动作循环与实际尺寸验收 |
| 高清素材降低 IDE 响应 | 预加载、图集缓存、缓冲分辨率上限、受限特效与声部；基于测量调档 |
| 重构期间五关行为退化 | 适配现有逻辑、按关迁移、持续保留 Lab 和阶段回归测试 |
| 构筑连锁无限递归或过强 | 根事件/触发深度、目标去重、预算与冷却、组合测试 |
| 读档重新领奖或丢失进化 | 稳定检查点、版本迁移、幂等奖励与重建一致性测试 |
| 完整范围过大，最后仅首关精致 | 建立全部素材/武器/世界完成矩阵，M2 只是中间成果，M6 要求全量覆盖 |

每个里程碑提交：可运行版本、完成清单、必要的真实截图/短录屏、相关验证结果、剩余问题。视觉目标选择集中在 M0；接口、缓存、测试组织等工程细节由实现方处理，不为日常可逆工作反复请求确认。

整轮完成必须同时满足：五关全量视觉与机制、六武器成长及进化、音频与设置、短任务与战役续玩、局外解锁与结算、存档迁移、正常试玩与性能/宿主验证、安装包和文档。只有计划、概念图、首关样板或新增类文件均不算完成。
