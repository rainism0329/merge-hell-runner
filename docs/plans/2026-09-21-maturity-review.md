# Merge Hell Runner：下一阶段成熟度评估

评估日期：2026-09-21。范围为当前 2.0.0 工作区；本轮只做审查，没有修改游戏实现。

**判断：已有内容足以支撑一款完整游戏。下一阶段应重点提高战斗组合、关卡因果、操作反馈和长期使用的可靠性。现有 Java2D 架构仍能承载这些改进。**

本轮重新编译生产代码及预览辅助程序，生成 68 张中英文、960×600 / 600×400 的实际 Swing 渲染截图，人工抽查其中 11 张。截图由现有 `LanguagePreview` / `HeapGameHarness` 设置场景并调用生产渲染路径；部分使用练习模式或人为设置结算状态。因此它们用于界面检查，不证明正式战役可通关、奖励正确或实机性能。截图在 `build/maturity-audit-20260921/flow/`；文本记录为同目录 `displayed-text.txt`。

代码审查覆盖战斗/章节、玩家流程、运行与发布。仓库记录的 745 项测试是既有结果，本轮没有重跑全量测试，也没有完成原生 IDE 真人通关或性能测量。以下将代码事实、设计建议和待验证风险分开描述。

**沿玩家流程的检查**

1. **进入游戏——需改进。** 已有角色、武器、难度、继续和练习入口。但有存档时，最突出的按钮仍是新战役，Continue 位于下面。截图确认信息层级；代码确认新开会写入口存档。建议已有存档时默认 Continue，新开明确告知替换范围。[菜单截图](../../build/maturity-audit-20260921/flow/zh-CN-menu-600.png)；[实现](../../src/main/java/com/bigphil/mergehell/render/MenuLaunchRenderer.java#L38)。

2. **设置与操作——基础良好，输入流程未完整。** 双语、静音、自动射击、震动、闪光、高对比度都已有，抽查设置页在 600×400 下可读。代码显示设置页忽略鼠标点击，没有改键和独立字号；主菜单也没有完整的方向键导航。建议统一键盘和鼠标操作，再加动作映射与字号设置。[设置截图](../../build/maturity-audit-20260921/flow/zh-CN-settings-600.png)；[输入实现](../../src/main/java/com/bigphil/mergehell/GamePanel.java#L475)。

3. **选择升级——信息已清晰，决策空间可加深。** 卡片已经展示实际数值变化，不需要再堆解释。当前候选过滤主要检查武器相关性和等级上限，没有互斥成长方向；在充分升级的情况下构筑趋同。建议增加少量有代价的分支，并提供整局构筑查看页。[升级截图](../../build/maturity-audit-20260921/flow/en-upgrade-600.png)；[候选规则](../../src/main/java/com/bigphil/mergehell/progression/UpgradeDraftService.java#L67)。

4. **进入 Boss 战——视觉身份明确，阶段策略需深化。** 第三至第五章已经有明显不同的场景和 Boss 轮廓。静态截图不能证明动作质量；代码显示后三章主要按固定循环选招，最终 Boss 的终局阶段还有招式收敛问题。需要针对阶段设计新的有效策略。[第三章截图](../../build/maturity-audit-20260921/flow/zh-CN-world-3-boss-960.png)、[第五章截图](../../build/maturity-audit-20260921/flow/zh-CN-world-5-boss-960.png)；[选招实现](../../src/main/java/com/bigphil/mergehell/boss/ChapterBossEncounter.java#L175)。

5. **暂停与离开——需优先改进。** 暂停页仍写“从关卡入口续玩”，实际已有段落存档；应展示真实保存位置及可能回退的范围。模拟暂停后仍持续发布整帧，CPU 影响需要实测。隐藏工具窗已有停止循环，不能将两者混为一谈。[暂停截图](../../build/maturity-audit-20260921/flow/zh-CN-pause-600.png)；[暂停文字](../../src/main/java/com/bigphil/mergehell/GameRenderer.java#L296)、[绘制循环](../../src/main/java/com/bigphil/mergehell/GamePanel.java#L895)。

6. **失败与再试——需优先改进。** Game Over 页只提供 New Run；代码中的 Q 返回菜单不包含该状态，全部生命耗尽还会清除检查点。建议补充重试当前配置、返回菜单、练习刚才的 Boss，并明确战役与有限生命挑战的不同规则。[失败截图](../../build/maturity-audit-20260921/flow/en-game-over-600.png)；[菜单条件](../../src/main/java/com/bigphil/mergehell/GamePanel.java#L369)、[失败处理](../../src/main/java/com/bigphil/mergehell/GamePanel.java#L1525)。截图使用人为设定的失败状态，不代表一次实际死亡记录。

**优先级 1：让每场战斗和每个机关都有意义**

**A. 从单兵种波次进化到有配合的遭遇。**

后四章的 `WaveDef` 每波只有一种敌人，下一波要等存活敌人为零；`MIXED` 标签没有实现多兵种组合。这不代表所有场景都没有敌人重叠，但锁屏波次本身缺少组合编排。[波次结构](../../src/main/java/com/bigphil/mergehell/LevelManager.java#L405)、[出场条件](../../src/main/java/com/bigphil/mergehell/LevelManager.java#L284)。

建议每章先做两场精品遭遇：盾兵守桥、高处狙击手封路、攀援兵从侧面逼迫移动；玩家可以先绕到高处，也可以打断侧袭再突破。用出场时机、空间、职责和威胁预算调难度。验收重点是存在清楚的目标优先级和至少两种解法，不能把所有敌人同时开火当成难度提升。

**B. Boss 换阶段必须改变玩家打法。**

最终 Boss 第三阶段把两个器官清零，失去器官的触手与孵化动作又全部退化成孢子扇，因此招式收敛成爬行与孢子攻击。这是明确可改善的设计结果，不等同于程序崩溃类缺陷。[器官变化](../../src/main/java/com/bigphil/mergehell/boss/ChapterBossEncounter.java#L118)、[招式替代](../../src/main/java/com/bigphil/mergehell/boss/ChapterBossEncounter.java#L252)。

建议保留可学习的招式，增加部件状态、距离、场地变化驱动的有限分支和独立终局动作。每次阶段变化至少改变一种有效策略；重要攻击有读得懂的起手动作和确定的承诺方向。断肢应继续减少对应威胁，不能马上补一个更强的同类招式，抵消玩家的成就感。

**C. 机关真的改变世界，章节用不同方式推进。**

五章探索结构目前统一为两个必访点和一个秘密点。第二章阀门确实改变水深，其他探索节点多数表现为完成标记、分数和日志；已有配重、冷却装置、膜门和巢穴，应继续深化。[探索结构](../../src/main/java/com/bigphil/mergehell/world/ExplorationRoute.java#L94)、[事件处理](../../src/main/java/com/bigphil/mergehell/GamePanel.java#L990)。

以下是基于现有机制的深化方向；已实现的输送带、冷却和水位机制将继续扩展：

| 章节 | 主导体验 | 值得做的代表段落 |
|---|---|---|
| 第一章：仓库之城 | 街区突围、屋顶绕行 | 地面受压制时经维修通道登楼，切断探照灯电源打开另一条进攻路线；秘密办公室用环境细节讲工程师的故事。 |
| 第二章：堆内存区 | 水位、泄漏、资源取舍 | 排水开放近路，也暴露原本被水阻挡的敌群；保留水位可通过浮台取得补给。 |
| 第三章：天空构架城 | 高低差、吊装、路线重构 | 绞盘真正移动桥面，货台载人穿越火力区；打断吊装装置改变首领战中的掩体或通路。 |
| 第四章：地热铸造厂 | 输送、热量、攻城压力 | 输送带迫使玩家管理站位，冷却装置创造短时安全区；Boss 冲锋后留下可读、短暂的场地变化。 |
| 第五章：异星巢心 | 活体地形、器官联动 | 摧毁神经结关闭孵化区并打开捷径；最终 Boss 脱离巢体后以独立终局动作交战。 |

每章至少一处交互改变可走区域或敌人布局，一条支路存在收益取舍，并有“认识机制→战斗中运用→高潮验证”的节奏。四角色都能走通主路，恢复存档后机关状态和奖励保持一致。关卡可以丰富，但不宜只继续加长步行距离。

**优先级 2：让角色、武器和表现值得反复体验**

**角色与构筑。** 当前角色主要通过速度/承伤倍率区分，工程师增加有限的设施回血；建议每人增加一种改变操作或目标选择的特性。例如侦察员空中位移、守卫主动格挡、工程师部署可收回的维护装置。先验证一个角色和一把武器的两条进化路线，再推广；分支必须带来射程、节奏、机动性或目标优先级的取舍。不要用永久攻击加成破坏刚建立的平衡。[角色定义](../../src/main/java/com/bigphil/mergehell/progression/CharacterId.java#L5)。

**视觉与手感。** 当前角色已有动作状态、瞄准和肢体连接，不需要再把“建立骨架”当成新功能。进一步可做专门的攻击起手/回收动作、起跳蹬地、落地受力、按材质区分的命中反馈。当前角色的手持 cannon 部件按角色选择，未随六种武器切换；让武器基础形态与进化形态在轮廓上可辨，比继续增加小尺寸贴图细节更有价值。[角色姿态与绘制](../../src/main/java/com/bigphil/mergehell/render/ActorVisuals.java#L149)。

改进现有接触阴影与场景受光的融合，加强局部受光和轮廓处理，让水、金属与组织的粒子和受击响应更加可辨。Boss 的破坏状态、退缩动作和死亡过程应形成完整的连续动作。声音可以增强层次，但游戏仍默认静音，任何重要提示都必须能靠画面理解。具体效果需以运动中的录像和实玩检验，静态截图不足以下结论。

**学习和反馈。** 增加约一分钟、可跳过的操作训练；按已见过的 Boss/阶段进入练习；暂停时查看整局构筑，失败后显示可信的致命来源和对应练习入口。改键后，教程与提示必须同步显示新键位，这是微软输入可访问性指南也明确强调的原则。[Xbox Accessibility Guideline 107](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107)

**重复游玩与奖励。** 首通 RP 已记录，但生产代码未见余额展示或消费入口。先决定用于外观、档案、基地陈列，或移除无用途的奖励文案；不要把目前开局可用的六把武器重新包装为解锁奖励。战役打磨后，再复用精品场景做 3–5 分钟单章挑战、Boss 连战、固定种子挑战码；成绩附带角色、武器、难度与规则版本，无须在线账户。[RP 记录](../../src/main/java/com/bigphil/mergehell/persistence/MergeHellStateService.java#L68)。

**架构如何支撑后续制作**

目前的限制主要在内容表达：单一敌人波次、固定选招、同构的探索标记、角色差异和动画资源。Java2D 能继续支持分层动画、局部光效、可动地形和更复杂的状态机；没有证据要求现在迁移 3D 或重写引擎。

技术工作跟随内容需求逐步推进：把遭遇的兵种/时机/位置、机关状态与通路、Boss 阶段和动作参数从面板协调逻辑中分开，并提供快速预览入口。先使一章制作顺畅，再抽出共性；暂不优先建设大型通用关卡编辑器。

运行方面已有固定步进、后台渲染和安全帧缓冲。下一步可让多步模拟追赶只发布最终一帧，避免绘制马上被覆盖的中间帧；真正 60Hz 或插值迁移放在计时标定之后。发布流程再加入声明支持版本的 Plugin Verifier 与原生安装冒烟，不能仅凭打包成功推断未来所有 IDE 版本兼容。

**建议执行顺序与验收**

1. **先补成熟度缺口：** 存档保护、失败流程、暂停资源占用、输入与设置一致性；同步建立最终 ZIP 的原生 IDE 基线。
2. **选第三章做完整样板：** 两场混合遭遇、一处真实移动通路、一条支路、一场每阶段有不同策略的 Boss 战，同时做对应动作和材质反馈。第三章的高低差、吊装和部件 Boss 可同时检验这些能力。
3. **实玩通过后推广五章：** 每章以自己的主题设计机制和节奏。最终 Boss 的终局招式收敛可作为独立的小批次优先改进。
4. **再做角色/构筑分支与重复挑战：** 先小范围验证玩法差异和平衡，再扩展数量。

每轮记录段落耗时、死亡来源、武器击杀时间、升级选择和 Boss 各阶段时间。先覆盖六武器、四角色和各难度的代表组合，再针对风险扩展；让新玩家与熟练玩家在真实 IDE 里体验，避免只由熟悉规则的人验收。自动探针适合验证边界和可通行性，不能代替对公平、紧张感、动作清晰度和休息节奏的判断。

这一轮最值得投入的完整批次是：**可靠的进出游戏流程，加上一章从敌人配合、机关变化到 Boss 阶段都精做的样板。** 它能同时建立产品质量底线与后续四章的制作标准。
