### 重复执行命令

以下命令在仓库根目录执行；先前生成的源码参数文件使用正斜杠绝对路径，避免 javac 把反斜杠作为转义字符。

```powershell
$baselineJbr = 'E:\JetBrains\IntelliJ IDEA 2025.1.3\jbr\bin'
$baselineIdeLib = 'E:\JetBrains\IntelliJ IDEA 2025.1.3\lib\*'
$baselineJunit = 'build/baseline-20260910/junit-platform-console-standalone-1.10.0.jar'

& "$baselineJbr\javac.exe" --release 17 -encoding UTF-8 `
  -cp $baselineIdeLib -d build/baseline-20260910/manual/main `
  '@build/baseline-20260910/manual/main-sources.args'

& "$baselineJbr\javac.exe" --release 17 -encoding UTF-8 `
  -cp "build/baseline-20260910/manual/main;$baselineJunit;$baselineIdeLib" `
  -d build/baseline-20260910/manual/test `
  '@build/baseline-20260910/manual/test-sources.args'

& "$baselineJbr\java.exe" '-Djava.awt.headless=true' `
  -cp "$baselineJunit;build/baseline-20260910/manual/main;build/baseline-20260910/manual/test;build/baseline-20260910/input/src/main/resources;$baselineIdeLib" `
  org.junit.platform.console.ConsoleLauncher execute `
  --scan-class-path=build/baseline-20260910/manual/test `
  --exclude-engine=junit-vintage `
  --config=junit.jupiter.extensions.autodetection.enabled=false `
  --reports-dir=build/baseline-20260910/manual/reports `
  --details=summary --disable-ansi-colors
```

## 4. 固定输入与时间基线

使用临时 `BaselineTimingProbe.java` 调用冻结代码的真实 `Player.update`、`GameLoop` 和 `ScheduledTickScheduler`。场地为无平台的平地，起点 x=100，地面 y=480，起始未升级构筑。数据来自重新编译的冻结源码，未改动角色常量或调度实现。

| 项目 | 测量结果 |
| --- | --- |
| 右移 125 个逻辑 tick | 625 px，即 5 px/tick |
| 单跳最大离地高度 | 134.4 px |
| 单跳顶点 / 落地 | 第 22 / 44 个更新 tick（第 1 个更新消费跳跃请求） |
| 冲刺距离 / 有效 tick | 80 px / 8 tick |
| 冲刺结束后的冷却 | 45 tick |
| 真实调度 125 个间隔 | 2.008834 秒，约 62.225 Hz |
| 旧调度配置 | 16 ms/tick，名义 62.5 Hz |

最后一行是源码配置；上一行是一次短采样实测。该采样用于确认当前时钟约为 62.5 Hz，不是长期 FPS、EDT 性能或操作延迟统计。较早一次原有编译产物采样为 2.003889 秒 / 62.379 Hz，符合调度抖动范围。

| 武器 | 连续射击间隔 | 按旧 16 ms/tick 换算 |
| --- | --- | --- |
| Commit Cannon | 18 tick | 288 ms |
| Force Push / SPREAD | 26 tick | 416 ms |
| Rapid CI | 8 tick | 128 ms |
| Garbage Collector / HEAVY | 25 tick | 400 ms |
| Firewall / FLAME | 12 tick | 192 ms |
| Refactor Beam / LASER | 30 tick | 480 ms |

武器探针通过现有 `giveWeapon(..., 999)` 入口逐个测量，不累加弹丸更新，只记录新增弹丸所在 tick；随机暴击不影响发射间隔。各行毫秒数是配置换算，不是逐武器真实按键延迟测量。完整输出位于 `build/baseline-20260910/timing-probe.txt`。

迁移到 60 Hz 时应显式处理这些差异。若仍保留原每 tick 数值，移动速度会从名义 312.5 px/s 变成 300 px/s，18 tick 武器间隔会从 288 ms 变成 300 ms。
