# M6 美术性能与实体预算短基准

日期：2026-09-11。状态：**素材升级前基线与视觉冻结版同探针对照已完成。** before-art 使用已通过 295 项正式测试的生产二进制；after-art 使用独立视觉冻结输入，具体范围见后文。两轮都没有修改生产代码、实体上限或正式 `build/classes`，未启动 GUI 或 Gradle。

本报告是 JDK 17 下 headless Java2D 调用耗时与短时资源观察，**不等于实际 IDE FPS、输入延迟、长期内存稳定性或 M6 性能目标已达成**。

## 真实执行路径与输入

冻结输入位于 `build/art-performance/before-art/main/` 和 `resources/`，复制自正式验证成功后的 `build/classes/java/main/` 与 `build/resources/main/`。日志确认 `GamePanel` 从冻结目录加载；输入清单为 `build/art-performance/before-art-input-sha256.txt`。素材只有该版本原有的城市图及代码绘制角色；后续图集和背景缓存优化没有混入此输入。

测量工具 `build/art-performance/tools/ArtPerformanceProbe.java` 调用真实：

```text
注入单步时钟 → GameLoop → GamePanel.actionPerformed
                        → 模拟 / 碰撞 / 动画 → FrameMailbox.publish
SwingUtilities.invokeAndWait → EDT → GamePanel.paint → FrameMailbox.paint
```

- Oracle JDK 17.0.12，真实 IntelliJ IC 232 SDK API，`-Xms256m -Xmx512m -Djava.awt.headless=true`。进程检查没有活动 IntelliJ Application，存档服务仅使用该进程内的 fallback，不写用户 IDE 设置。
- 每个物理尺寸创建独立 GamePanel，经菜单 START 和关卡入口流程进入固定 seed 的第 1 关。静音、无自动开枪，测试角色使用现有 LAB 无敌设置，避免负载采样被死亡界面打断。
- 固定输入由工具准备：普通 6 敌人、32 己方投射物、12 敌方投射物、120 粒子；高负载从实际 `EntityLimits` 读取 40 / 320 / 180 / 1,200。逐帧 CSV 证实所有采样的实际数量均等于目标，没有因弹体出屏或粒子过期而降压。
- 每步在计时外补足受控场景；敌人对象持续复用以保留动画历史，位置约束在画面中；弹体和粒子在画面内补充。补充对象的构造不计入模拟调用耗时，但其分配会出现在堆 / GC 观察中。这是受控预算负载，不是自然关卡试玩。
- `simulation_publish_ms` 包含真实模拟、碰撞、动画、逻辑画布渲染和帧发布；`edt_paint_ms` 包含 EDT 上绘图上下文创建、真实 `panel.paint` 与缩放；排队等待单独记录为 `edt_dispatch_ms`。
- 物理尺寸为 960×600、600×400、1280×800。600×400 保留真实黑边，实际游戏画面 600×375；其余画面等于物理尺寸。
- 无 wall-clock 帧率 sleep，循环尽快运行，每步仅推进 16 ms 模拟时间。每组先预热至少 250 ms，再采样至少 1,250 ms；百分位只描述调用耗时，不能把样本数 / 时间换算为实际 FPS。

复用入口：

```powershell
./build/art-performance/run.ps1 -Label before-art -JavaHome 'E:\Java\jdk-17.0.12'
```

本次 after-art 已冻结在 `build/art-performance/after-art/main/` 与 `resources/`，用 `-Label after-art` 运行同一工具。before-art 输入与数据保留原样。

## 六场景耗时

单位为毫秒；列内为 **p50 / p95 / max**。本轮共 300 个测量样本，总墙钟用时 **18.985 秒**，含首次类 / 字体 / 资源初始化及面板建立关闭。

| 负载与物理尺寸 | 样本 | 模拟 + 发布 | EDT paint | EDT 排队 p95 |
| --- | ---: | ---: | ---: | ---: |
| 普通 960×600 | 51 | 19.260 / 39.509 / 41.717 | 1.880 / 2.534 / 2.629 | 0.193 |
| 普通 600×400 | 61 | 17.399 / 20.048 / 20.577 | 3.200 / 4.115 / 4.440 | 0.200 |
| 普通 1280×800 | 44 | 15.158 / 19.407 / 20.388 | 12.287 / 17.222 / 17.541 | 0.152 |
| 高负载 960×600 | 51 | 22.638 / 27.075 / 28.058 | 1.749 / 2.372 / 2.534 | 0.211 |
| 高负载 600×400 | 54 | 19.829 / 24.755 / 26.987 | 2.644 / 3.691 / 3.749 | 0.150 |
| 高负载 1280×800 | 39 | 20.297 / 25.943 / 26.196 | 11.325 / 15.529 / 16.421 | 0.142 |

该环境中，高负载全部模拟 / 发布样本超过 16 ms；普通场景比例分别为 92.16%、70.49%、38.64%。这是后续同环境对比和定位的线索，不能直接推断 IDE 里的丢帧率。1280×800 的软件缩放 paint 成本明显更高，也不能据此断言真实 IDE 的硬件加速路径具有相同开销。

第一组面板创建约 8,953.5 ms，后五组约 118.5–154.0 ms；前者含冷类加载、资源与 Java2D / 字体初始化，未拆分归因，不等同于实际 IDE 中工具窗口启动耗时。250 ms 是短预热，不能证明 JIT 已完全稳定；首组普通 960 的尾部耗时尤其应谨慎解释。

首次探路运行使用 1,750 ms 采样窗口，连创建关闭共 22.019 秒，已保存在 `before-art/pilot-results/`；为满足短基准范围，正式可复用入口缩短至上述 1,250 ms。探路时普通 960 的模拟 / 发布 p95 为 22.303 ms，说明短样本、预热与机器并行负载存在明显波动。后续素材前后比较须使用相同工具与设置，不把单次 p95 的细小变化当作确定回归。

## 内存、线程与发布

| 观察点 | 堆使用 | 已提交堆 | 线程数 |
| --- | ---: | ---: | ---: |
| EDT 初始化后、显式 GC 后的起点 | 20.401 MiB | 256 MiB | 11 |
| 全部面板关闭后 | 218.373 MiB | 256 MiB | 12 |
| 关闭后显式 GC，再等待 100 ms | 24.482 MiB | 256 MiB | 12 |

- 测量过程中自然 GC 3 次，计入的 GC 时间增量 9 ms；起点和末尾的显式 GC 不属于场景耗时采样。
- 原始数据记录每组 heap used / committed、non-heap used、线程数、GC 次数和时间。结束后 non-heap 约 23.94 MiB，包含类加载和 JIT；结果 CSV / 测量容器也由工具保留，堆前后差不能直接归因于游戏泄漏。
- 300 / 300 次测量均观察到新帧发布；这条短基准顺序执行模拟与 EDT paint，没有模拟慢读者竞争，因此不等同于并发压力下零丢帧。
- 六个 FrameMailbox 全部关闭，反射只读诊断确认保留的栅格缓冲数为 0。末尾线程列表不含 `MergeHell-Audio`；额外保留的 Java2D / AWT / JVM 线程已写入日志。

## 视觉冻结版 after-art 对照

after-art 在北京时间 2026-09-11 00:54:59 冻结。先完整复制最近成功编译的 `build/art-integration/classes/` 到独立 `after-art/main/`，再将当时的 11 个授权视觉源复制到 `after-art/overlay-source/`，仅编译这些冻结副本覆盖独立输出：`assets/*.java`（包含逐级缩小缓存）以及 `ActorVisuals`、`IndustrialArt`、`IndustrialDeck`、`LegacyBossRenderer`、`GameRenderer`。编译使用 JDK 17、真实 IC 232 SDK 与快照 classpath，并设置独立 sourcepath 和 `-implicit:none`；**没有重新编译正在修改的 GamePanel、Player、GameSession 或存档服务**。资源完整复制自当时的 `src/main/resources/`，包含 RGBA 图集与城市背景。

### after-art 内存和初始化观察

| 观察点 | before 堆使用 | after 首轮堆使用 | after 第二轮堆使用 |
| --- | ---: | ---: | ---: |
| 初始显式 GC 后 | 20.401 MiB | 20.401 MiB | 20.433 MiB |
| 全部面板关闭后 | 218.373 MiB | 164.127 MiB | 136.414 MiB |
| 关闭后显式 GC | 24.482 MiB | 24.541 MiB | 24.580 MiB |

三轮已提交堆都为 256 MiB，初始 11 个线程、结束 12 个线程。after 首轮自然 GC 增量 **18 次 / 25 ms**，第二轮 **11 次 / 26 ms**，before 为 **3 次 / 9 ms**；这些统计包含面板建立、受控负载准备和采样，不能当作每帧分配率。关闭后显式 GC 的存活堆接近，但这两次短跑仍不足以证明长期无泄漏。日志末尾没有 `MergeHell-Audio` 线程。

after 首轮第一面板建立约 8,782.8 ms，后五组约 214.8–308.1 ms；before 后五组为 118.5–154.0 ms。初始化成本有所增加，未单独拆分图集解码、缓存建立和 JVM 冷启动；这是后续优化的另一处观察点。
