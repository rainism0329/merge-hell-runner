# Heap District 机制与集成契约

`world.HeapDistrictController` 仅用于第二关（level 1）。它不生成整套关卡、不引用 Player/Boss、不读写存档，也没有渲染或墙钟依赖；根任务负责接入真实主循环、碰撞、奖励及 Boss 破防/回血 API。

## 路线选择

三个路线 GC 站中心位于世界 x = 760、2600、4650，站体 48 × 76，底部使用输入 groundY。玩家距离中心横向不超过 70 px 且位于地面附近时可交互：

- **E 净化**：48 个有效 tick（0.768 秒）通道，离开范围取消；完成后清除镜头内泄漏/回流，降低 25 压力，发一次 20 XP / 300 分奖励。
- **F 风险回收**：立即发一次 30 XP / 600 分奖励，提高 25 压力并尝试布置一个有完整预警的泄漏池；池数和间距限制始终优先。
- 两种成功选择都把路线站标为 USED，没有反复刷奖励的入口。可以绕过全部站继续至 Boss，没有隐形硬门槛。

压力范围 0–100，影响后续泄漏间隔（625 − 2 × 压力 tick）。泄漏池最多两个，每个 120 × 14，位于地面；池与池之间至少保留 120 px 空地，不生成地形或覆盖平台路径。每池先预警 60 tick（0.96 秒），再激活 250 tick（4 秒）；预警期不伤害。激活池只输出碰撞到地面玩家的 8 点伤害事件，全部池共享 60 tick 间隔，实际无敌帧和伤害处理归 Player。离开当前镜头范围的旧池会被丢弃。

## Boss 回流与 GC 窗口

首次真实 Boss 活动输入把镜头原点固定为场地原点，在 +190、+470 放置两个 Boss GC 站，之后镜头运动不移动它们。Boss 站只接受 E；通道完成后冷却 750 tick（12 秒），清理当前可见危险并输出 150 tick（2.4 秒）破防窗口。Boss 站不发 XP 或分数。

回流内存块最多两个，26 × 26。出现后先预警 30 tick，此时控制器拒绝 `hitBlock`；预警结束后向输入的真实 Boss 中心移动。根任务确认枪弹 swept hit / 近战交集后调用 `hitBlock(id)`，一次有效命中即可截断；同一个 ID 重复命中无效，输出 75 tick（1.2 秒）破防窗口。GC 也能清除可见回流块，其事件标记 `byGc = true`，随后 GC 总窗口保持 150 tick。

未拦截的回流块到达 Boss 时最多输出 12 点回血，整场最多 96 点；上限按本次遭遇累计，复活不重置。控制器不直接修改 Boss HP，也不降低普通攻击伤害。根任务消费窗口及回血事件，保留 Boss 既有行为和攻击逻辑。

## 真实状态驱动的短剧情

初入进水口、首次越过 1800（失联档案库）、4000（回流总管）、6200（主泵室）揭示旧内存保留、GC 停机和错误保护回流。首次节点选择补充对应后果；Boss 入场按已净化/回收的站数反馈；阶段 2、3 的真实变化和首次破防窗口各有一次短句。阶段因回血下降后再上升不会重播。

当前短句保留 240 tick。故事采用有序等待队列，最多两条；队列满时丢弃最旧的待播提示，当前提示不被同 tick 新事件覆盖。一次越过多个区域只保留最新到达区域，回退不重播。`Story` 事件在真正开始显示时发出，避免日志与当前画面同时刷出整个队列。`snapshot.objective` 立即反映通道、交互、回流或破防状态，不需要等待故事播完。

## 根任务接入顺序

1. 新关入口/续玩入口使用 `standard(levelSeed)` 新建控制器；非 Heap 关卡不启用。
2. 有效游戏 tick 调用 `update(Input)`，输入当前玩家 bounds、镜头、地面、真实 Boss bounds/stage/active。先 `drainEvents()` 处理环境伤害；确认玩家仍存活且没有待显示升级后才消费 E/F 的单次输入调用 `interact`，随后再次 `drainEvents()`。奖励打开升级时停止剩余战斗碰撞，致死在升级显示前结算。
3. 真实弹丸/近战碰撞确认后调用 `hitBlock(id)`，随后再 `drainEvents()`。只有返回 true 才消费这次弹丸命中。
4. `Cleaned`：按事件发奖励，清理 `clearedArea` 中允许清除的有限敌弹，并调用 Boss 窗口 API。`RefluxBroken` / `RefluxArrived` 分别调用窗口/有界回血；`DamagePlayer` 交给实际 Player；`Story` 交给日志/字幕。
5. 暂停、升级、hitstop 不推进控制器，或传 active=false；后者保持同一已发布快照，交互与命中返回 false。
6. 复活调用 `resetTransient()`，清池/回流/未完成通道，保留 USED、已赚奖励、Boss 站冷却和回血预算，并提供至少 180 tick 新安全时间；同时调用 Boss.clearVulnerability() 清除实际增伤。跨关与继续入口重新构建，沿用现有入口 checkpoint，不新增任意帧存档。

所有快照列表和值几何不可变，`Bounds.rectangle()` 每次新建用于旧碰撞 API 的适配对象。渲染只能读取快照，动画依据 snapshot.tick；不得推进计时或自行制造危险状态。

## 独立验证

生产新控制器和测试均以 JDK 17 `javac --release 17` 独立编译到 `build/heap-validation/`，未改正式 `build/classes`，未运行 Gradle。确定性、预警精确边界、暂停、通道取消、一次奖励、池间距/平台安全、双 Boss 站锚定与冷却、回流预警/截断、回血上限、复活保留资源和故事队列均有普通 `@Test`。

最终专项 **19 / 19 通过**，2 个容器，0 跳过/中止/失败，465 ms；见 `build/heap-validation/console.log` 与 XML `build/heap-validation/reports/`。这组测试验证控制器契约；完整主流程、实际 Boss 伤害窗口、视觉可读性和真实游玩由根任务集成验收。
