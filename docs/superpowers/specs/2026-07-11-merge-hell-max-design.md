# Merge Hell Runner MAX 设计规格

日期：2026-07-11
状态：已由用户逐节确认

## 1. 产品目标

Merge Hell Runner MAX 是运行在 IntelliJ IDEA 工具窗口中的横版动作 Roguelite。它的核心承诺不是高压挑战，而是让开发者在 12–18 分钟内完成一次从谨慎求生到火力失控的解压过程。

五个主题关卡组成可跨多次 IDE 使用完成的战役。每个关卡是一局独立任务，通关进度会保存，不要求玩家一次完成整个战役。

成功标准：

- 新玩家在 60 秒内理解移动、跳跃、射击和当前目标。
- 一局任务在正常难度下持续 12–18 分钟。
- 第一次改变手感的升级在开局 90 秒内出现。
- 一局至少产生三次明确的火力高潮：首次流派成型、SUDO 爆发和最终 Boss 构筑验收。
- 失败不会抹除全部收益，玩家能明确知道死亡原因并愿意立即重试。
- 工具窗口隐藏、项目关闭或音频失败不会影响 IDEA 稳定性。

## 2. 核心体验曲线

单局采用以下节奏：

`热身跑酷 → 小规模战斗 → 第一次构筑 → Arena 爆发 → 恢复区 → 精英事件 → 构筑完全体 → Boss`

战斗导演通过威胁预算交替安排 45–90 秒的压力段和 10–20 秒的喘息段。喘息段用于恢复、选择升级、展示新区域或预告危险。游戏不会持续无节制刷怪。

击杀产生 Build XP。升级时模拟暂停，并提供三个升级卡片，玩家可按 `1/2/3` 或点击选择。约每 60–90 秒升级一次；连续两次没有出现当前构筑关联选项时触发保底，每局提供一次免费重抽。

连击同时积累 Overclock。蓄满后自动进入 8 秒 SUDO：提升射速和穿透，增强屏幕表现并叠加音乐层。SUDO 是可预测的周期性奖励，不依赖低概率随机掉落。

每个关卡包含安全节点。死亡消耗一个进程生命并从最近节点恢复；整局失败仍保留部分永久资源和已发现图鉴。低血量或短时间连续受伤会提高恢复掉落概率，但不会暗中降低敌人伤害。

进度只保留三层：即时连击、单局构筑、战役永久解锁。MAX 版不增加额外日常任务、在线货币、赛季或联网账户。

永久资源只有一种：Refactor Points。精英击杀、首次通关和 Boss 评价会产生 Refactor Points，用于解锁新主武器、核心模块和初始 Loadout，不购买永久伤害或生命数值，避免后期只能依靠数值碾压。

## 3. 操作与构筑

玩家主动控制移动、双跳、冲刺、朝向和主武器射击。一个主武器、两个被动模块槽和一个自动充能的 SUDO 能力构成完整 Loadout。自动射击作为设置项提供，默认关闭。

六把武器拥有独立战斗语言：

| 武器 | 基础机制 | 进化 | 进化效果 |
| --- | --- | --- | --- |
| Commit Cannon | 精准、暴击、弹射 | Cherry Pick | 在敌群间自动连锁并复制暴击 |
| Force Push | 近距离散射、击退、贴脸高伤 | Force Push --force | 半屏冲击波与强击退 |
| Rapid CI | 高速射击、Heat 累积 | Pipeline Storm | 自动追踪并在满热时进入狂暴 |
| Garbage Collector | 慢速重弹、贯穿、范围删除 | Full GC | 击杀触发连续范围回收 |
| Firewall | 持续灼烧、残留火墙 | Zero Trust | 火墙环绕玩家并拦截普通子弹 |
| Refactor Beam | 短蓄力、直线贯穿、命中折射 | Mass Refactor | 周期性全屏扫描并连锁折射 |

主武器达到五级且取得对应核心模块后，在下一次精英事件中进化。升级选择必须改变行为、决策或可感知反馈，不加入只有微小百分比变化的填充选项。

升级池分为武器、移动、无人机、暴击、护盾和连击六类。所有路线都能通关，不设置依赖外部攻略才能识别的失败组合。

捡到新武器时显示“替换 / 转化为模块 / 拒绝并获得 XP”，不会直接覆盖当前构筑。

## 4. 敌人与战斗公平性

敌人按职责设计：

- Bug：低血量群体单位，提供连锁击杀和恢复节奏。
- Conflict：显示瞄准线后远程射击。
- Crash：高速自爆，爆炸会伤害其他敌人。
- Lock：释放可击破连接线，短暂限制冲刺但不夺走移动控制。
- Tech Debt：重甲单位，破甲后分裂为多个弱小 TODO。
- Firewall：带安全缺口的移动墙体，可跳跃、冲刺或火力突破。

所有危险攻击必须遵守：生成后无即时伤害；高伤害动作提前 400–700ms 预警；屏幕外攻击有方向指示；颜色之外还使用形状和运动表达危险类型。

Arena 目标包括清理敌群、删除错误节点、守护 CI 和限时连续提交。目标持续 45–75 秒，失败造成奖励降低或额外敌群，不直接结束整局。

## 5. 关卡与 Boss

五个关卡共享基础操作但拥有独立规则：

- Dark：标准战场，建立规则并让第一套构筑成型。
- Monokai：移动平台、代码地雷和高连击敌群。
- Solarized：周期性昼夜切换，不同敌人在对应阶段暴露弱点。
- Nord：低摩擦区域和风道，强化冲刺与空中射击。
- Dracula：腐化区域扩张，击杀精英净化场地并获得增益。

每个 Boss 持续 90–150 秒，拥有三个行为阶段。阶段变化由机制而非单纯血量增长构成，并包含短慢动作、标题卡、音乐变化和安全输出窗口。

- Legacy Code Monstrosity：依赖节点保护本体，玩家需要拆解依赖链。
- Memory Leak Daemon：内存块压缩安全空间，玩家可触发 GC 反杀。
- The Architect：实时建造墙体、炮塔和平台，改变战场结构。
- Kernel Panic Overlord：分割战场并通过清晰安全区组织弹幕。
- Singularity Engine：复制玩家当前构筑并混合前四个 Boss 的标志机制。

Boss 不使用无法跳过的长动画，不在阶段转换期间偷袭，不通过超长无敌时间拖延战斗。

## 6. 视觉与界面

视觉方向为“JetBrains 原生感 × 赛博街机”。游戏实体使用统一的 Java2D 矢量造型，代码文本作为辅助符号，不依赖跨平台表现不一致的 Emoji。

画面使用 960×600 固定内部逻辑画布并按工具窗口等比缩放。背景分为主题渐变、远景服务器、代码雨、网格和前景数据流等视差层。窄窗口启用紧凑 HUD，不简单缩小全部字体。

反馈层级：普通命中使用轻微火花和音色变化；暴击增加短 Hitstop、方向性碎片和数字强调；精英击杀、武器进化、SUDO 和 Boss 转阶段才使用全屏级表现。这样保持高潮稀缺并减少视觉疲劳。

首页包含任务选择、Loadout、永久解锁进度和一键继续。游戏 HUD 只显示生命、Build XP、武器、连击、Overclock 和当前目标。事件日志默认折叠为两行。升级界面提供三个大卡片，明确描述行为变化和实际数值。结算页展示流派、伤害构成、最高连击、死亡原因和新解锁。

首次出现冲刺、进化和 Arena 目标时展示一次性情境提示，不使用长篇教程弹窗。

设置项包括震屏强度、CRT、闪光、粒子密度、主音量、自动射击和高对比度。减少动态效果时不移除必要的攻击预警。

## 7. 音频

音效和音乐采用轻量程序化音频，避免大型资源包和第三方版权依赖。每把武器拥有独立音色、命中层和轻微音高变化，连续射击不会机械重复同一声音。

音乐包含探索、Arena、SUDO 和 Boss 四层，根据战斗状态平滑增减。默认音量克制；工具窗口隐藏、失焦或暂停时淡出，重新获得焦点后淡入。`M` 可立即静音。音频初始化或设备切换失败时静默降级，不阻塞游戏循环。

## 8. 技术架构

现有 `GamePanel` 和 `GameRenderer` 将按职责拆分：

- `GameLoop`：固定 60Hz 更新、时间累积和掉帧保护。
- `GameSession`：任务、玩家、构筑、分数与状态机。
- `InputController`：把 Swing 输入转为线程安全命令。
- `PhysicsSystem`：移动、平台、冲刺、跳跃与空间碰撞。
- `CombatSystem`：伤害、状态、爆炸、连锁、暴击、击退。
- `EncounterDirector`：威胁预算、遭遇和恢复段。
- `ProgressionSystem`：Build XP、升级、进化和永久解锁。
- `AudioEngine`：音乐层、音效、淡入淡出和静音。
- `GameRenderer`：只消费不可变 `RenderSnapshot`，不改变世界状态。

武器、升级、敌人、任务和 Boss 使用 `WeaponDefinition`、`UpgradeDefinition`、`EnemyDefinition`、`MissionDefinition` 等定义对象。可组合策略承担具体行为，替代集中式 `switch`。

逻辑循环运行在插件拥有的单线程调度器上；Swing EDT 只处理输入分发、不可变快照交换和绘制。逻辑掉帧时最多追赶有限帧数，避免恢复焦点后执行大量历史更新。

工具窗口隐藏时暂停循环和音频，项目关闭时通过 IntelliJ `Disposer` 释放线程、Timer 和声音资源。

## 9. 存档、错误与性能

存档使用带 schema 版本的 IntelliJ `PersistentStateComponent`，保存战役进度、解锁、设置和排行榜。现有 `PropertiesComponent` 排行榜自动迁移；无法解析的数据回退到默认状态并记录一次警告。

音频或可选视觉效果失败时单独禁用对应功能。游戏循环未捕获异常会停止当前任务、保存可恢复进度、显示简洁错误页并写入 IDE 日志，不能传播到 IDEA 主事件循环。

弹丸、粒子、敌人和浮动文字设硬上限。达到上限时优先丢弃纯视觉元素；不能静默删除会影响伤害的逻辑实体。渲染避免每帧创建字体、颜色和大型临时集合。

性能验收：

- 目标 60 FPS；渲染 EDT 的常规帧耗时低于 8ms。
- 960×600、250 个逻辑弹丸和高粒子设置下仍能保持可操作性。
- 连续运行 15 分钟后，实体数量回落时堆使用量不持续单调增长。
- 隐藏工具窗口后不再执行世界更新，音频在 300ms 内淡出。

## 10. 测试与交付

所有游戏逻辑使用可注入时钟和确定性随机种子。测试覆盖：

- 六把武器、进化和状态效果。
- 升级保底、重抽和进化条件。
- 敌人预警时间、出生保护和屏外攻击提示。
- 五个 Boss 的阶段转换与失败恢复。
- 15 分钟无输入、持续射击、极限实体和完整任务模拟。
- 多个工具窗口尺寸的 `BufferedImage` 渲染冒烟测试。
- 窗口隐藏、重新打开、失焦和项目关闭的生命周期。
- 旧排行榜迁移与损坏存档回退。

每个阶段必须通过 `test`、`buildPlugin` 和插件配置验证。最终在 `runIde` 中完成完整 Dark 任务、整场战役抽样和性能观察。

## 11. 分阶段范围

第一阶段交付高质量垂直切片：新架构、Dark、Commit Cannon、Force Push、升级选择、Overclock、新 HUD、新 Legacy Boss、存档迁移和性能基线。

下一份实施计划仅覆盖第一阶段。第一阶段验收通过后，第二、第三阶段分别编写独立实施计划，避免把完整 MAX 版压缩成一次高风险重写。

第二阶段扩展 Rapid CI、Garbage Collector、Firewall、Refactor Beam，以及剩余四个关卡和 Boss。

第三阶段完成程序化音频、无障碍设置、结算统计、数值调优、长时间压力测试和商店素材更新。

联网排行榜、多人模式、用户自定义 Mod、云存档和外部服务不属于 MAX 版范围。
